03Phases

Each follows its written spec. What is recorded here is the delta from this session's code read.

AThe contract iv fieldFirst

ivRank is a percentile — where today's vol sits inside its own year — not a volatility. It cannot substitute for the real thing. The value is already computed server-side and simply never sent.

  • ContractDetails gains iv: Optional[float] = None, populated from the existing bs_iv.
  • bs_iv returns None when it cannot converge. Carry iv: null through. Never substitute a default, never fall back to ivRank / 100.
  • The Contract Details card renders IV 34.5% beside IV rank, per the schematic. — when null.

Done when iv is on the wire and on the card, and a non-converging contract renders a dash rather than a plausible-looking number. No gate change yet.

BGate basis and thresholdsAfter A

The gate is evaluated at a stop that moves — Check structure and Compute Arithmetic Plan both change it. A scan-time precompute cannot serve it, and a TypeScript pricer is rejected: there is not one Math.exp in frontend/lib/ today.

So the endpoints that produce a stop also return its cost. The card never computes; it renders what it was given and prints the inputs.

  • StructuralStopRequest gains four optional fields — strike, dte, premium, iv — present together or not at all. A partial set must 422. Silently skipping the gate because one field was missing is how a contract with no verdict reads as an unremarkable one.
  • New StopCostOut; /contracts/exit-plan gains the same block against final_stop.price. The two will legitimately disagree — assert that, don't treat it as a bug.
  • Do not fork an alias route: the stocks-mode card calls this same endpoint, which is why the new fields are optional.
  • Frontend stopPremiumRisk becomes a presenter. The Δ-linear arithmetic is deleted, not kept as a fallback — a fallback that quietly answers a different question is worse than no answer.
  • capped and the (uncapped …) tail go away; Black-Scholes cannot exceed the premium on a long option. I counted 21 capped references across risk.ts, its tests and TradeCard.
  • There are three stop_premium: blocks in scoring_rules.yaml, all reading 0.8. All three move.
Basis and thresholds must move together

Under the new ruler the worst contract on the reference chain reads 77% — beneath the old Swing line of 0.80. Keep the old thresholds and the gate goes permanently silent.

CPiece 3 — scan-time finalStopAfter A

This is what makes pieces 1 and 2 take effect by default. Today, on any card where the Arithmetic Plan button was never pressed, Monte Carlo still sends the flat −3%. The bug an early handoff called the worst factual wrongness on the card is currently fixed only for people who click an optional button first.

  1. Call compute_final_stop per symbol at scan time and attach exit.finalStop. structuralSource and distanceDollar are required — the "Bottom (final stop)" row reads both. Wrap in asyncio.to_thread; assembly point is scan.py:863.
  2. stop.contractPrice cannot exist at scan time — it needs a contract. Contract-priced sub-cells render — until a plan is computed. Say so explicitly.
  3. Survive a Step 6 override. mergePlan does exit: plan.exit, a wholesale replacement, and TradeExit has no finalStop — so it would be wiped for exactly the cards where a contract was hand-picked. Add it to TradeExit, echo it back, and splice it in withCachedEstimate as defence in depth.
  4. Migrate the store. scanStore is at version: 12. Bump to 13 with an explicit migration branch. Pre-13 restores render "not computed — re-run the scan", never a blank and never a silent PASS.
  5. Ranking badge. Add exactly two fields to WatchlistRow — stopCostPct and stopCostStatus. Not five. Adding strike/dte/premium/iv/delta to every row so the client could price it would be the TypeScript-pricer decision by the back door. The badge must say it describes the auto-picked contract.
DPiece 4 — per-position premium stopIndependent

There are three global premium-stop percentages today and no per-position field at all. Changing the global silently re-arms every open position at once.

  • premium_stop_pct = Column(Float, nullable=True, default=None). NULL means "inherit the global" and is a distinct, load-bearing state — a position stamped 0.60 at creation would stop responding to a global change, which is exactly today's behaviour and the thing this removes.
  • Settable at creation, not update-only. active_tp_method is on the update schema only; do not repeat that. A trade sent from the card must carry the stop or its first alert silently uses the global.
  • One shared resolver for all three alert paths. scanPortfolio currently takes a single premiumStopPct for every position — resolve inside the loop. A preview that disagrees with the alert that later fires is worse than no preview.
  • Both send paths carry it. They already disagree about stop re-anchoring; do not add a second field they disagree on.
  • The drawer distinguishes inherited from set: 60% (global) vs 45%.
EPiece 6 — stocks arithmetic planIndependent

There is no stocks gate. Q-A is closed. The gate measures what share of the premium a stop costs — a question that exists only because of an option's nonlinearity. A stock's stop cost is exact, and sizing already covers it. Do not build a badge that looks like the options one but answers a different question.

  • compute_final_stop and compute_target_row take no contract input — they survive verbatim. estimate_rr and the gate are dropped.
  • New POST /stocks/exit-plan, because the contracts route requires strike > 0, dte and premium > 0.
  • Carry both guards over: < 2 candles and atr <= 0 both 422. Without them the ATR floor collapses to the entry price and every target lands on entry — a "computed" plan built on no data.
  • Disclose the day-count difference. Options counts calendar days; the stock engine counts trading days. Do not silently unify — ship daysBasis and render "~10 trading days".
  • Include the stop's probability. "This stop is reached on 34% of paths, typically in 6 trading days" is the most decision-relevant number on the card, and it comes free in the same call.
  • Assert on the schema's key set that no premium, strike, DTE, IV, delta or stop-cost field appears — so an options field cannot leak back in later.

The spec also recommends the two-barrier stock version of the Barrier Race. Flagged as an addition, not assumed — it needs your yes.

FHeston calibrationSpec first

heston_cache.py:36 has v0_grid = [0.04] — one value, 20% vol, hardcoded for every symbol on every scan, while the reference contract has 34.5% IV. The pricer is fine; the calibration is the defect, which is why plain Black-Scholes is currently more accurate than the shipped Heston.

Seed v0 from the chain's own ATM IV — the correct seed already exists in the file and is used only in the fallback path — fit relative or vega-weighted error instead of absolute dollars, and use Heston only when its measured RMSE beats the BS baseline on the same chain.

04Three conflicts in the source documents

Found by reading the chain end to end. Resolved here so the next session does not re-litigate them.

  1. The ranking badge's basis. Round 4 says use the delta-linear basis and that "no decision is pending". The later gate-basis spec says the backend computes it with Black-Scholes and the row carries only the result. The spec wins — it is later, it is what Q3 decided, and the schematic's own summary table independently lists the ranking badge under Black-Scholes at today's date. Round 4's text was written while the card gate was still Δ-linear; leaving both live would put two different rulers on one screen.
  2. A stale line number. The piece-6 spec cites first_passage.py:275; the function is at :714.
  3. Who owns iv. Round 4 treats it as part of piece 3; the gate-basis spec treats it as shared. Pulled out as Phase A here so neither piece owns it and the payload is touched once.

05Traps carried forward

  • np.argmax on a boolean row returns 0 both for "hit on day 1" and "never hit". Pair every argmax with .any(axis=1).
  • dte < 1 returns probability 0.0 for every target — a refusal to simulate, not a real zero. Four zeroes summing to 0% look like a computed answer.
  • The backend re-anchors stops on save. Defensible for a percentage level, wrong for a structural stop, which is an absolute chart level.
  • No stop order exists anywhere. All four paper adapters are MKT or LMT. Everything called a "stop" is an in-app alert.
  • Grep before removing. capped has 21 references, and an earlier handoff's "129 KB" estimate was wrong by more than 2000×. Verify; do not repeat a prior note.
