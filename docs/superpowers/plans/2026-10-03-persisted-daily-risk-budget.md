# Phase B2 — persistent daily risk budget across order paths

Goal: trading review #9. Preserve A6's full-premium daily opening budget, persist it across restarts, cover manual and automatic opens, and include gross realized losses recorded in the portfolio. Profits and history deletion never replenish the budget. The deliberately conservative formula is today's retained opening reservations + today's recorded negative realized P&L + the prospective opening risk <= server account value * auto_trade.max_daily_loss_pct. A same-day losing close therefore adds loss on top of the opening spend; this stage does not recycle spent opening budget after closes. Call it a daily risk budget in messages, not a measurement of actual losses or fills.

Database:
- Main application DB, new DailyRiskBudget(day primary key, reserved_cents, loss_cents) and DailyRiskAttempt(id primary key, day, reserved_cents, state/outcome, immutable instrument/source/quantity metadata). A separate unique closed-row-id DailyRiskLoss entry makes realized recording idempotent and independent of deletable closed trade history.
- Integer cents; reserve rounds prospective exposure upward and configured allowance downward. Reject nonfinite/nonpositive money or values outside signed integer capacity. Validate daily fraction finite within[0,1]; unreadable explicit limits fail closed, never disable risk checks. Account value comes from B1's server resolver.
- Migration from the current single Alembic head; import models for metadata and create-all test workflows. Existing attempts cannot be reconstructed from process-only auto history. Before ANY manual or auto reservation, bootstrap available current-day auto history keyed by stable attempt_id. Never predicate import on an empty ledger: earlier manual reservations must not suppress importing retained auto attempts. Unique attempt IDs make repeated bootstrap idempotent. Known accepted/ambiguous rows retain full recorded premium; definite refusals/rejections do not. Before any reservation, also bootstrap existing current-UTC-day negative ClosedPositionModel rows using server closed_at and recorded realized_pnl_dollar into unique DailyRiskLoss events. Use the same idempotent loss recorder as live closes; bootstrap and live recording must not double charge. Bootstrap failure prevents dispatch.

Service interface and atomicity:
- daily_risk.reserve(attempt_id, instrument/quantity/price/source metadata) owns a fresh AsyncSession transaction. Ensure day row idempotently, then conditionally update reserved_cents only when existing reserved+loss+new <= current limit. Insert the unique attempt in the same transaction and commit before dispatch. Concurrent manual and auto attempts must not both consume the remaining balance. Retry only insert races, with rollback. A duplicate attempt returns its original reservation or refuses mismatched input; never charges twice.
- daily_risk.resolve(id, definitely_not_submitted) releases only a still-retained attempt proven unsubmitted or explicitly rejected, atomically with its state change. Accepted, unknown, exception after dispatch, client cancellation and abandoned worker outcomes retain reservation. No automatic expiry/refund; day boundary is UTC actual pre-dispatch time, not user dates.
- daily_risk.record_realized_loss(db, closed_row) inserts the loss event and increments that UTC day's loss_cents INSIDE the close transaction; does not commit separately. Amount is max(0,-recorded realized_pnl_dollar), server UTC close time. Each partial close event is unique. History deletion leaves budgets and loss events intact. Short-stock realized P&L must have the correct sign; long puts remain long-premium positions regardless of bearish direction.

Order integration:
- Manual broker OPEN endpoints: reserve after existing idempotency leadership and successful credential/order construction, immediately before execution inside the worker. A sync bridge submits the reserve/resolve coroutine onto the originating loop via run_coroutine_threadsafe; do not run global AsyncPG pools on a new worker loop. Using the same bridge for manual and auto makes day and concurrency checks occur at dispatch rather than while queued.
- Opening long options reserve quantity*100*maximum prospective premium. LMT uses the positive buy limit (the maximum payment); MKT requires a finite positive server quote. Naked short option opens are refused because premium received is not a loss bound. CLOSE orders bypass the budget and remain available even if configuration/ledger is unusable.
- Stocks reserve quantity*server quote/limit notional (a conservative opening-spend proxy, not a worst-case bound for short stock). No missing quote or zero-risk bypass. Shorts' realized close loss is still accounted correctly.
- Auto fire and scan-triggered fire use injected daily-risk hooks captured from the caller's live event loop. Existing _FIRE_EXECUTOR and scan worker remain. No optional production path silently falls back to only in-memory history. Keep existing old-history gate as an additional conservative check if useful, but durable gate always runs before execute. Resolve errors after dispatch never convert accepted orders into not-submitted, erase history, or block booking; retain budget and log the reconciliation failure.
- Portfolio POST/basket tracking does not reserve (it places no order). Already-placed auto booking keeps gates disabled, records the ordered quantity and does not reserve again. Qty drawer bookkeeping is not broker dispatch and does not create a broker reservation.
- Explicit broker rejection statuses and IBKR unanswered confirmation release. Unknown statuses/errors retain. Cancellation after worker begins retains; ensure worker completion can finalize after HTTP handler cancellation (request lifetime is not worker lifetime). Pre-dispatch service failures must prevent execute, with an explicit refusal history/status where applicable. Direct-send 422 refusal preserves existing client rollback behavior.

Testing and audit:
- Atomic concurrent manual+auto reservations near limit; duplicate/changed attempt; restart and UTC rollover; cent boundary and invalid config/quotes; limit lowered before execution.
- Opening spends, gross loss from full/partial/short-stock closes, wins do not refund, history delete cannot reset, repeated close-event recording charges once.
- Tracked saves and post-broker booking consume no additional budget; CLOSE succeeds with unusable daily config; raw manual OPEN and both auto triggers cannot bypass.
- Explicit rejection/no-submit/IBKR confirmation release; accepted/unknown/error/cancelled-worker retains; DB failure before order prevents execute; DB failure after order preserves actual order/booking classification.
- Test SQLite transactions plus compile/inspect PostgreSQL-safe atomic SQL; migration up/down in isolated SQLite and Alembic one-head check. Full backend/frontend/typecheck/build after integrations.
- Separate plan and code audit stages, max three fresh independent rounds each, shrinking fixes; no broad Phase A or unrelated Phase B expansion.

Deferred: precise recycling of closed exposure, broker-fill reconciliation, persisted full auto-trader UI history, multi-process scheduler design, brokerage-account live balances, and multiyear strategy adoption. These do not weaken the retained-reservation gate.
