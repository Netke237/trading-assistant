## Source findings and implementation boundary

`stock_scan.py` routes Pre/Fib list responses through `run_reported_scan`; Pullback routes the actual stock scan with `req.category == 'pullback'`. The existing durable envelope has schema_version 1, run_id, category generation, frozen dispatch/current inputs, result and diagnostics. Keep that envelope, its retention rules, five categories and transport metadata. Add a separately versioned `diagnostics.terminal_outcomes` object to the matching run, rather than another scan or a replacement response. Existing diagnostics keys, StockPipeline, rejected lists and accepted results remain available.

Pre currently silently omits absent bars, exceptions and `breakout_setup_signal(...) is None`. Fib also omits `level_hit is None` and an observed wrong-side EMA comparison. No named compression/range/trend rule failure is supplied by either engine's generic missing signal. Do not modify engines to infer reasons, replay them, or calculate missing measurements.

The stock funnel's `classify_stock_rejection` is unsuitable as this contract's terminal classifier: `failed_history` includes price-filter failures and configured exclusions, `other_rejected` is a residual rather than proof of an exception, and shortlist is a post-ranking removal. Obtain new observations at the existing decision sites. Do not parse arbitrary provider exception text or backtest summary text. Preserve current StockPipeline counters and their actual definitions.

## Additive contract

`terminal_outcomes` contains `version: 1`, `resolution_available`, `complete`, ordered `input_symbols`, ordered `evaluated_symbols`, ordered `outcomes`, `counts`, and `unknown_symbols`. Identity comes from the containing immutable envelope; never fabricate another ID. `input_symbols` is the unique resolved, nonblank candidate set before exclusions. It is not the count of submitted universe tokens. Frozen request retains the original submitted list.

Each outcome has `symbol`, `terminal`, `code`, optional `observations` (finite typed measurements), and optional `thresholds` (finite applied values). Terminal values are `accepted`, `excluded`, `no_data`, `error`, `no_setup`, `filtered`. Input and evaluated are stage counts, not extra terminal categories. An evaluated symbol is one whose per-symbol evaluation starts, including a history fetch that returns no data or raises; configured exclusions are never evaluated. Each input symbol receives at most one final outcome. Final accepted means retained in the returned candidates after any shortlist cap, not merely a signal or preliminary PositionCardOut.

For a complete run, unique input equals accepted + excluded + no_data + error + no_setup + filtered; evaluated equals input minus excluded. Every count is calculated from collector records, never from universe minus displayed rows. For a partial run, counts describe recorded outcomes only; unknown_symbols identifies inputs without a recorded terminal outcome. Unknown is not error/no_setup, and complete is false. If resolution failed before its set was known, input/evaluated counts are null rather than zero. Legacy/missing/unsupported-version objects are unavailable, not complete zero-count reports. Empty successfully resolved input produces a complete object with real zero counts.

`filtered` is required to represent observed Fib EMA filtering and real Pullback gates honestly. It is neither configured exclusion nor generic no setup. There are no overlapping per-rule counts in version 1. Recorded observations describe only the first terminal decision actually taken; earlier passes are not a record of all engine checks.

## Deduplication and numerical preservation

Before exclusion filtering, data access, quote fetch, evaluation and counting, normalize resolved Pre/Fib tickers with the existing strip/uppercase behavior and keep the first occurrence of each nonblank symbol. Apply the same normalization/deduplication to Pullback's category-specific resolved list; do not modify the original frozen request. Use a small shared pure helper in stock_scan.py. Preserve universe/manual precedence separately for each endpoint (Pre/Fib universe first; stock core nonempty symbols first). Exclusion filtering already deduplicates excluded entries but retains duplicate kept entries, so deduplication must precede `_drop_excluded_symbols`.

For the shared stock core, apply this new candidate-set behavior only when `req.category == 'pullback'`. Ordinary Stocks and scheduled Stocks behavior remains unchanged. Worker observations activate only for a collector configured for this contract, so shared analysis helpers/direct worker callers remain valid. Pullback's `_scanned` and existing pipeline receive the same deduplicated list actually dispatched, preserving their reconciliation.

Preserve the first-occurrence universe order as the stable tie order. Keep Pre's confidence-descending sort, Fib's at-level/distance sort and stock `_shortlist_rank_key`, cap, score, confidence, sizing, strategy/backtest calls and existing numerical expressions intact. For unique inputs every candidate field/order must match baseline; duplicate inputs must match running the existing pipeline on the first-occurrence unique input, with one evaluation per symbol. This explicitly removes duplicate evaluations/rows, rather than claiming byte equality to a duplicate baseline. Do not reorder by terminal codes or deduplicate after ranking/capping.

## Decision-site mapping

| Pipeline decision | Terminal / safe code and measurement |
|---|---|
| Scan-policy exclusion, all three modes | excluded / scan_policy; no arbitrary exclusion reason copied. Existing projected reason-unavailable disclosure stays. |
| Pre/Fib empty bars | no_data / missing_history |
| Pre/Fib history fetch exception | error / history_fetch_failed; no exception text |
| Pre/Fib signal/detail exception | error / signal_processing_failed |
| Pre signal is None | no_setup / setup_not_returned; underlying rule unknown |
| Fib level_hit is None | no_setup / fib_level_not_returned; insufficient bars versus no swing unknown |
| Fib actual bullish close < EMA or bearish close > EMA branch | filtered / ema_side; record already computed current_close, ema_value, applied integer ema_period and direction. Equality remains accepted by this filter. EMA off or insufficient bars does not count as a failure. |
| Final Pre/Fib row | accepted / candidate_returned |
| Pullback <60 daily bars / no price / required insufficient intraday bars | no_data / insufficient_history, missing_price, insufficient_intraday_history respectively; actual existing requirements |
| Pullback `_regime_data_drop` | no_data / regime_data_unavailable when bars missing without fetch exception; error / regime_fetch_failed if its existing fetch exception caused the drop. Observe this at the caller with the actual exception-presence flag, never parse interpolated reason. |
| Pullback price min/max return | filtered / price_min or price_max; existing price and applied threshold |
| Pullback rejected card or `_min_score_drop` | filtered / score_status or score_min; existing card score/status and applied min where relevant |
| Pullback `_direction_conviction_drop` | no_data / trend_unmeasured for its unmeasured branch; filtered / direction_conviction for the measured below-floor branch. Use the same already loaded rule/threshold, not a new measurement. |
| Pullback regime headwind return | filtered / regime_headwind |
| Pullback signal None | no_setup / setup_not_returned; strategy pullback_ema, no invented EMA-specific cause |
| Pullback `_backtest_drop`, confidence-reject branch | filtered / backtest_gate or confidence_gate; record safe numeric fields actually present, never summary text |
| Pullback caught worker exception or gather exception | error / data_processing_failed; no str(exc) in new diagnostics |
| Stock candidate trimmed by existing cap | filtered / shortlist_cap; existing cap/rank/original_count |
| Retained Pullback PositionCardOut | accepted / candidate_returned |

Unknown/unrecognized returned rejection dictionaries get an unknown terminal outcome (leave symbol in unknown_symbols), not a guessed error. Category does not constrain the backend strategy field: a caller can submit another allowed strategy with category pullback. Record its actual strategy. Existing multi-signal misses can be recorded as generic no_setup at their actual `_multi_signal` drop sites; unknown-strategy returns are error / unsupported_strategy. Do not call these EMA failures. If an uninstrumented reachable drop remains, the run must be partial; a residual reason classifier cannot clear complete. Direct producer tests must cover every reachable stock worker return and shortlist removal.

## Collector, persistence and safe projection

Extend `Collector` with a category-scoped terminal recorder, first-occurrence resolution/evaluation order and an outcome map. Add explicit begin-evaluation and terminal-observation functions. Snapshot the parent collector's shared data safely through asynchronous worker ContextVars; no await inside recording mutations. Record worker drops where they occur, but finalize accepted/shortlist outcomes after gather/sort/cap. A preliminary built candidate is not terminal accepted. Conflicting finalization cannot silently overwrite an outcome: retain incomplete state and a fixed diagnostic-unavailable indicator. No diagnostic bookkeeping failure may change a candidate or broker value.

`run_reported_scan` merges the object with current pipeline/list diagnostics when finishing the same callback. On callback failure/cancellation, persist recorded partial outcomes and known unknown inputs on the existing failed/cancelled run; preserve safe error codes and rethrow/metadata behavior. Startup interruption before records are saved remains diagnostics unavailable; do not promise recoverable per-symbol logs. Serialization/save failure retains existing persistence-unavailable behavior and response metadata. Do not change begin/finish transactions, generation ownership, latest/previous pointers, pruning, category attribution or source ScanSession data.

Create a dedicated typed projection/validator for terminal records in scan_report_lifecycle.py: allow fixed terminal/code enums, valid ticker strings, actual known directions/strategies, finite numeric measurement/threshold keys and booleans. Construct records from these values only. Do not broadly permit free strings in `project`, raw exceptions, stack traces, provider objects, arbitrary reason/detail strings or configuration source strings. `error` is a terminal enum value under key `terminal`; never use the forbidden payload key `error`. New contract validation must survive `scan_reports._encode` and preserve unavailable markers. No new migration is required for this additive JSON member; no old envelope rewrite.
