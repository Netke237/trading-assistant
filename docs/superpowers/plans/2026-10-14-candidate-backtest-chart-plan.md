# Candidate backtest chart — approved design and implementation plan

Phase: `CANDIDATE-BACKTEST-CHART`. Planning only; implementation is not authorized by this document. User requested feature documentation and tickets after grilling and approved every recommendation below. Independent plan review must pass before child tickets are published. Implementation follows the board workflow when scheduled.

## Approved behavior

Available from both Stocks and Pre-Breakout. Existing Jump/Open Chart navigation opens the full chart workspace with the clicked candidate's identity attached, preserving its existing same-tab/new-tab behavior. Candles with actual historical entry/exit markers appear above a separate equity panel. Strategy equity and long buy-and-hold start at index 100 on the same evaluation window. They share time navigation and a crosshair; price and equity retain separate units and scales.

Default to the candidate's original backtest, with its original dates, fees, strategy, direction, parameters, sizing and candle interval displayed. Buy-and-hold remains explicitly long even when the strategy is bearish. Clicking a trade shows actual fill timestamps/prices, direction, recorded exit reason and net return. Unclosed positions are separate from closed trades; no fabricated exit. A successful zero-trade result retains its real curve and benchmark. Missing, expired, unsupported and failed results are distinct from successful zero trades. Offer an explicit fresh run when original results are unavailable, clearly marked as a new result; never silently substitute it for the scan's evidence. Interval changes never rerun a backtest implicitly.

## Source facts and compatibility boundaries

- `backend/app/services/strategy_backtest.py` computes `stats['_equity_curve']` but `BacktestResult` only exports aggregates. `run_strategy_backtest_trades` exposes closed records with date-only timestamps, insufficient for intraday markers. Preserve that public contract while adding a separately typed detailed result from the SAME engine invocation.
- Original stock backtests run in `backend/app/routers/stock_scan.py`, using resolved parameters, commission, horizon/hold and daily or intraday bars. Cache keys exist, but current aggregate caches are not sufficient evidence of exact historical OHLCV or full run identity. Do not regenerate a run and call it original, even with matching parameters.
- Backtest engine uses initial cash 100,000 and exclusive orders. Read actual effective order sizing/commission semantics from the engine and freeze them; scan execution shares/risk are not this simulated sizing.
- Pre-Breakout and Fibonacci confidence is setup evidence, not `BacktestResult`. Pullback confidence can also differ from stock strategy backtest statistics. Existing ticket #118 proposes additional Pre-Breakout backtests; this phase does not implement that strategy work or silently map setup modes to `breakout_base`/`pullback_ema`.
- Pre-Breakout's current Open Chart passes symbol only and opens a new tab. In-memory candidate objects cannot be assumed available in that tab. The chart workspace's existing live overlays are not historical backtest fills.
- This phase waits for #235 because it touches the Pre-Breakout page. Preserve #150 / PR #224 and audit counters on their existing phases. No incidental merge or closure.

## Detailed data contract and correctness requirements

Use an immutable, versioned server-side artifact with an opaque ID referenced additively by a candidate. Resolve original artifacts by ID, never by symbol, current settings, latest report or row index. Artifact identity includes scan/report run ID, candidate symbol, strategy, direction, horizon, effective entry/exit parameters, hold policy, applied commission, actual engine sizing/cash configuration, candle interval, evaluation start/end, creation time, exact input-bars fingerprint and engine contract version. Freeze original bars, equity samples, fills, open-position evidence and aggregates together. Return copies so mutable caches cannot alter frozen evidence. Bounded retention may expire an artifact; expiry must be explicit and must never resolve to another run. Additive absent fields preserve legacy data. Use project authentication/access boundaries; artifact IDs must not bypass authorization.

Capture stock detailed data during the original backtest invocation (including cache hits through a detailed identity-safe cache), not a second invocation. Failures saving optional artifacts must not alter scan ranking, gates, candidate eligibility, aggregates or order behavior; return original-unavailable. Legacy aggregates cannot be upgraded by recomputation. Avoid persisting large chart payloads to browser scan stores; use versioned migrations only if existing persisted shapes require breaking changes. Server persistence uses existing repository storage conventions and a migration if a new table is necessary; exact artifact serialization/retention mechanism is decided from existing storage code and documented before build.

Detailed successful result carries finite chronological timestamps, input OHLCV, engine equity in native account currency, initial equity, closed trades with unique IDs, exact EntryTime/ExitTime including intraday precision and actual fills, per-trade net return, known recorded reason or explicitly unknown, optional open-position evidence, and original summary statistics. Extract from actual engine outputs, do not derive equity by adding trade percentage returns. Preserve existing date-only TradeRecord users. Invalid/nonfinite values cause explicit unavailable evidence, never a fake zero or invented curve. Engine exceptions/insufficient history/unsupported strategy must carry an explicit non-success status rather than inheriting `_empty`'s zero aggregates as successful runs.

Evaluation window follows the existing engine's warm-up/window semantics. Align strategy equity, frozen candles and benchmark by timestamp on that exact window. Normalize each real series as `100 * value / original_positive_baseline`; strategy baseline and warm-up clipping must match the engine's return convention. Do not normalize from the first visible zoom sample. Explain any difference between indexed change and existing summary metrics; test reconciliation of ending equity with engine total return, allowing only documented rounding. Benchmark is the gross long stock close-price index on the same frozen bars, labeled 'Long buy-and-hold (gross; excludes fees)'. It is not a short benchmark or simulated fractional share portfolio. Display original strategy commission separately so cost differences are visible. No benchmark across incompatible currencies or different adjusted/unadjusted source bases.

Use epoch timestamps with explicit timezone/time-basis semantics; no local date truncation of intraday fills. Map markers to actual corresponding original candle timestamp/interval without snapping a fill to a different session. Marker prices/tooltips show fills, not candle close or current strategy targets. When multiple trades share a bar preserve every trade in an accessible detail list. Do not label inferred reasons as engine-recorded certainty. Open mark-to-market equity may affect the equity curve although closed-trade counts exclude open trades; disclose this and test it.

Fresh runs require explicit click and an explicit supported strategy, direction, parameters, window, costs and sizing. Prefill only captured known settings, never ambient substitutions for absent candidate settings. Unsupported setup strategies remain unavailable and may link to the existing Stocks backtest workflow for the user to configure a DIFFERENT supported strategy, clearly distinct from original setup evidence. New detailed artifacts have new IDs and provenance and do not mutate the selected candidate, scan report, confidence, gate, validation approval or trading inputs.
