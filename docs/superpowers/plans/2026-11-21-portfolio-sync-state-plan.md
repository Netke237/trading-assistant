# PORTFOLIO-SYNC-STATE plan (board item #661, umbrella #656)

Goal: always tell the trader how fresh the Portfolio numbers are: when the page last synced, when it is still loading, that the 30 s cycle pauses in a hidden tab, and when the P&L curve has stopped. Spec = issue #661 scope items 1-6 and the #656 mapping rows 3, 8, 26, 36, 73 (preview board 1). Frontend only. No backend change (the fields #658 added are already served), no new persisted field, so no store version bump. Nothing existing is removed.

## What exists today (read from the code, 2026-11-21)

- `frontend/app/(frame)/portfolio/page.tsx`: one `useEffect` runs `await syncFromBackend(); fetchPerformance()` plus `fetchHistory()` on mount, then a bare `setInterval(runCycle, 30_000)` (sync, then `scanPortfolio` -> `addToast`, then `fetchPerformance`). It never checks `document.visibilityState`. The tabs are two plain `<button>`s in `div.tabs`. The empty state (`styles.empty`, "No open positions.") renders whenever `positions.length === 0`, including before any sync has finished. `PnlChart` is rendered twice (History tab: equity + realized; Open tab: `openPnlCurve`, `defaultKind="open"`).
- `syncFromBackend` (`frontend/lib/portfolioStore.ts`, ~L1743-1880) returns `Promise<boolean>`: `false` on `!res.ok` or any thrown error (network, bad JSON), `true` after the positions were applied. It records no time. The store persists only `positions` (`partialize`, key `bamendjou-portfolio-v1`, version 8, `skipHydration: true`); every other field is in-memory.
- `frontend/lib/performanceStore.ts`: `Performance` has the three curves and four realized figures only. The backend already returns `lastSnapshotDate` (newest `equity_snapshots.snapshot_date`, `YYYY-MM-DD`, server-local date, `None` when no row), `snapshotSkippedOn` and `snapshotSkippedContracts` (process-local: the latest `GET /api/portfolio` that skipped the snapshot because of unquoted rows, contract ids; `[]`/`None` after a successful write, after a restart, or when no position is open). The frontend does not read these yet (`grep lastSnapshotDate frontend` is empty).
- `frontend/components/organisms/ConfigHealthBanner/index.tsx` is the visibility pattern to copy: `const visible = () => document.visibilityState !== 'hidden'`; the interval body is `if (visible()) pollNow()`; a `visibilitychange` listener re-polls on return; the listener and interval are removed in the effect cleanup. `hhmmss(ms)` (local time `HH:MM:SS`) is exported from `frontend/lib/configHealth.ts`.
- Backend alert monitor (`backend/app/services/portfolio_alert_monitor.py`): a server loop, default every 60 s (`checkIntervalSeconds`, minimum 15), independent of any browser tab. It calls `notify_alert` (Gmail/Telegram, filtered by `enabledTypes`, de-duplicated) and `alert_service.broadcast` (websocket). No frontend module consumes that websocket for portfolio alerts (grep finds only `chartWS`), so in-app toasts on this page come only from the page cycle's `scanPortfolio`.
- `frontend/lib/marketHours.ts` has ET session logic and no holiday calendar. The backend writes a snapshot on any successful, fully quoted `GET /api/portfolio` including weekends (`date.today()`, no weekday check).
- No existing test covers `PnlChart`. Existing page tests: `frontend/app/(frame)/portfolio/__tests__/{portfolioNumbers,quoteUnavailable,riskView,stopBreachBanner,...}.test.tsx`; they mock `PnlChart`, `PnlHeatmap`, `EditDrawer`, `ClosePositionDrawer` and set `syncFromBackend: jest.fn().mockResolvedValue(undefined)` (note: resolves `undefined`, not a boolean).

## Things the item assumes that do not match the code (and the minimal fix)

1. "Sync timestamps in `portfolioStore.ts`": none exist. Add three non-persisted fields (`lastSyncAt`, `lastSyncFailedAt`, `firstSyncAt`, all `number | null`, epoch ms). `partialize` keeps only `positions`, so no `version` bump and no `migrate` branch. A test pins that the persisted blob still contains only `positions`.
2. "Use `lastSnapshotDate` / skipped contracts from QUOTE-GAPS": present on the wire but dropped by `performanceStore`. Add them to `Performance` + `EMPTY_PERF`, plus a non-persisted `fetchedAt: number | null` on the store state (set on a successful performance fetch) so the page can tell "performance read after the first successful sync".
3. "Last trading day": there is no helper and no holiday calendar. Add `lib/tradingDay.ts` with weekday-only logic in America/New_York (rule in T1). Holidays are not modelled; the consequence is bounded and stated under the stale rule.
4. "Hydration error likely persisted store counts": ruled out, see the hydration section; the real cause is date labels.
5. A failed sync does not currently stop the alert scan: `runCycle` chains `.then(...)` on a `false` result and scans stale positions. T2 gates the scan on a successful sync (see interpretations).

## Interpretations (recorded, not asked: each is the narrowest reading of the item text)

- **Sync status line** sits under the heading row, in `styles.heading`'s column, a `Text size={11}`. Success: `Synced 17:42:10 · refreshes every 30 s, paused while this tab is hidden` (tone secondary; time = `hhmmss(lastSyncAt)`, local clock, same helper as the config banner). Failure (shown iff `lastSyncFailedAt !== null && lastSyncFailedAt > (lastSyncAt ?? 0)`): `Last sync failed 17:42:40, showing 17:42:10` (tone caution) when an earlier success exists, else `Last sync failed 17:42:40, showing positions saved in this browser` (the localStorage rows). Before any attempt finished: `Syncing…` (tone dim). A later success clears the failure text by the same comparison. Only the failure line has `role="status"`; the success line is not a live region (it changes every 30 s).
- **Failure detection**: `syncFromBackend()` resolving exactly `false` is a failure; `true` and `undefined` (the test mocks) are success. The store, not the page, stamps the times, inside `run()`: `lastSyncAt = Date.now()` right after the final `set` that applies the positions, `lastSyncFailedAt = Date.now()` at the `!res.ok` return and in the `catch`. A sync started by `InitStores` (dashboard poll) therefore also counts, which is correct: the numbers are as fresh as the last applied GET regardless of who asked.
- **Loading vs empty**: `syncAttempted = lastSyncAt !== null || lastSyncFailedAt !== null`. `positions.length === 0 && !syncAttempted` -> "Syncing positions…" (same `styles.empty` box, one `Text size={14} tone="secondary"`, `role="status"`). `positions.length === 0 && syncAttempted && lastSyncAt === null` (first sync failed, nothing known) -> "Could not load positions. Last sync failed {hh:mm:ss}." in caution tone; the "No open positions." empty-state text is shown only when `lastSyncAt !== null` (a real empty portfolio), unchanged text. Rows restored from localStorage render normally during the first sync (they are not blank); only the empty list is gated.
- **Alert scan gate**: the cycle scans for alert toasts only when the sync result is not `false`. Scanning positions whose prices did not refresh would raise toasts from stale quotes. `fetchPerformance` after a failed sync is skipped as well (the curve would be read without the preceding snapshot write).
- **Pause**: visibility only (`document.visibilityState`), not window `focus` (the item names visibility). On mount while hidden, the first cycle is deferred to the first `visible` event. Returning to visible clears and re-creates the 30 s interval and runs one cycle immediately (so the next tick is 30 s after return, not a double hit). A `cycleRunning` ref skips a cycle while one is still awaiting (the store also dedupes concurrent syncs, but the scan and the performance fetch are not deduped).
- **What happens to an alert while hidden** (documented in the code comment and the T2 report): the backend monitor keeps running and sends Gmail/Telegram (`notify_alert`, de-duplicated, `enabledTypes`) and the websocket broadcast. The in-app toast path is page-only: nothing is evaluated or queued while hidden. A condition that is still true when the tab returns raises its toast from the immediate return cycle (the scan is state-based; `addToast` de-duplicates on `alertKey`). A condition that came and went while hidden gets no in-app toast and nothing is replayed; the external notification is the record. No change to `alertEngine.ts` or `alertStore.ts`.
- **Tabs**: `role="tablist"` (`aria-label="Portfolio views"`) on `div.tabs`; each button `role="tab"`, `id="portfolio-tab-open|history"`, `aria-selected`, `aria-controls="portfolio-panel-open|history"`, roving `tabIndex` (0 on the selected, -1 on the other). Keys on a tab: ArrowRight/ArrowLeft move to the other tab and select it (automatic activation, wrap around), Home/End select first/last; focus follows. Existing visible labels stay: `Open (n)`, `History (n)`. Each tab's content is wrapped in `<div role="tabpanel" id=… aria-labelledby=… className={styles.panel}>`; `.panel` repeats `.main`'s `display:flex; flex-direction:column; gap: var(--space-4)` so layout is unchanged. The close dialog block stays outside the panels.
- **Stale rule** (below) applies to the two snapshot-based curves, Open P&L and Total value. The Realized curve comes from closed trades, not snapshots, and never shows the notice.
- **Dashed line**: for the Open P&L curve only, a dashed segment from the last point to `(referenceDay, openPnlToday)`, where `openPnlToday` is the same `openTotals(positions).openPnL` the footer and the notice show. For Total value no dashed line is drawn (today's total is not known without a snapshot); only the shaded gap and the notice. This is the default; if Kenneth wants a flat dashed extension instead it is a one-line change, but a flat line at the old value would assert a number that is not true, so it is not the default.

## Stale-curve notice rule (exact)

`lib/staleCurve.ts` exports a pure `staleCurveNotice(input): StaleCurveNotice | null`.

Input: `kind: 'open' | 'equity'`, `lastSnapshotDate: string | null`, `curve: PerfPoint[]` (the raw API curve for that kind), `positionsCount`, `openPnlToday: number`, `unquotedSymbols: string[]` (from `positions` with `quoteUnavailable === true`, symbol order of the table, unique), `skippedContracts: string[]`, `now: Date`, `ready: boolean`.

Returns `null` unless ALL hold:
1. `ready` (the page passes `firstSyncAt !== null && fetchedAt !== null && fetchedAt >= firstSyncAt`, i.e. a performance read happened after the first successful sync; before that the curve may predate the sync's snapshot write).
2. `positionsCount > 0` (the backend writes no snapshot with no open position, so an old last point is normal then).
3. `curve.length > 0` and `lastSnapshotDate !== null`.
4. `lastSnapshotDate < referenceDay` as ISO strings, where `referenceDay = lastTradingDayEt(now)` (`lib/tradingDay.ts`): take the ET calendar date of `now` (`Intl.DateTimeFormat('en-CA', { timeZone: 'America/New_York' })`); if it is a Saturday/Sunday step back to the Friday; if it is a weekday and the ET time is before 09:30 step back one weekday (Monday -> Friday). No holiday calendar: on an exchange holiday `referenceDay` is that weekday, so a curve whose newest snapshot is the previous session shows the notice until the page writes that day's snapshot (the first fully quoted sync does, as the backend writes on any weekday or weekend load). The notice is still true on those days (no snapshot exists for the reference day); documented, not special-cased.

`lastPoint` = the last element of `curve` after sorting ascending by `date` (never a resampled point, never a Days/Weeks/Months artifact). Its date must equal `lastSnapshotDate`; if they differ (should not) the notice uses `lastSnapshotDate`'s curve point if present, else returns `null` (never print a mismatched pair).

Text (`formatMoney(v, { plus: true })`, Unicode minus, `D MMM` from a manual month table, `D MMM YYYY` only when the year differs from `now`'s ET year; no `toLocaleDateString`):
- `open`: `Last point: {D MMM}, {lastValue}. Open P&L today is {openPnlToday}. {cause}`
- `equity`: `Last point: {D MMM}, {lastValue}. {cause}` (no Open P&L sentence)
- `cause` when `S` = symbols is non-empty: `No daily snapshot is written while a position has no quote ({S} now), so the line has stopped.` where `S` = `skippedContracts` mapped through `contract.split('|')[0]` and de-duplicated, else `unquotedSymbols`, joined with `, `.
- `cause` when both are empty: `No daily snapshot has been written since then. One is written when this page loads with every position quoted.`
- Worked example (item text): `Last point: 23 Oct, +$1,530. Open P&L today is −$37. No daily snapshot is written while a position has no quote (BMY now), so the line has stopped.`

Output also carries `lastPointDate`, `referenceDay`, `liveValue: number | null` (`openPnlToday` for `open`, `null` for `equity`) for the chart.

Chart rendering (`PnlChart`): props `staleNotices?: { open: StaleCurveNotice | null; equity: StaleCurveNotice | null }`; the active notice is the one for `kind`, none for `realized`.
- Notice: a `<p role="note">` (caution tone, `Text size={12}`) at the top of `.chartArea`, above the chart div.
- Axis extension: the line series data gets one whitespace item `{ time: referenceDay }` after the last point so the time axis reaches the reference day (v5 whitespace data).
- Dashed line (open only): a second `LineSeries` with `lineStyle: LineStyle.Dashed`, `lastValueVisible: false`, `priceLineVisible: false`, data `[{ lastPoint }, { time: referenceDay, value: liveValue }]`.
- Gap shading: an absolutely positioned, `pointer-events: none` `div[data-testid="stale-gap"]` over `.chartArea`, left edge `timeScale().timeToCoordinate(lastPointDate)`, right edge `chartArea width - priceScale('right').width()`, recomputed in `subscribeVisibleTimeRangeChange` and the existing resize handler; fill `color-mix(in srgb, var(--caution) 14%, transparent)`. Hidden when the coordinate is `null`. The text notice is the carrier of the facts; the shading is decoration with `aria-hidden`.

## Hydration error #418: root-cause hypothesis

React #418 is a server/client text-content mismatch. `PortfolioPage` is a `'use client'` page but Next still renders it on the server, and its render body computes `const now = new Date()` and builds `todayLabel`, `weekLabel`, `monthLabel`, `yearLabel` with `toLocaleDateString('en-GB', ...)` and `getDay()`/`getFullYear()`, which render in `PerfStat`'s period `Text`. The server's clock, time zone and ICU data differ from the browser's: across a midnight boundary or a time-zone offset the server prints a different day/week/month (and possibly a different month abbreviation) than the client, so the first client render disagrees with the HTML. That is a text mismatch on exactly this page, on every load near a day edge and on any load where server TZ differs from the browser TZ (here: server UTC, browser CET).

Persisted-store counts are ruled out: `usePortfolioStore` uses `skipHydration: true` and `StoreHydration`/`InitStores` rehydrate inside `useEffect`, so the SSR and first client render both see `positions = []`, and `history`/`performance` are non-persisted (`History (0)` on both). `PnlHeatmap` (`isoWeek(new Date())`, `fmtDay`) only mounts on the History tab, never on the SSR pass (initial `tab` is `'open'`).

Fix: `lib/useClientNow.ts`, `useClientNow(): Date | null` (`useState<Date | null>(null)`, set in `useEffect`, refreshed by the page after each successful cycle so labels also roll over past midnight). While `null` the four `PerfStat` period labels render no period text (the prop is already optional). The sync status line, the stale notice and anything else clock-derived read only effect-set state, never `new Date()` in render. Hidden-tab note: the refresh happens in the cycle, so it resumes on return.

Verification is mandatory before and after, because this is a hypothesis: (1) reproduce first with `npm run dev` on a spare port (never 3001) and read the console: dev builds print the exact differing text; if the diff names something other than the four period labels, fix that source if it is in the files this item touches, otherwise record it in the T3 report and open a follow-up issue rather than widen scope. (2) A Jest test renders `renderToString(<PortfolioPage />)` with fake time `2026-11-21T23:30:00Z`, then `hydrateRoot` into that markup with fake time `2026-11-22T10:00:00Z`, and asserts `console.error` was not called with a hydration warning (it fails on current code, passes after). (3) Production check: `next build && next start` on a spare port, load `/portfolio`, `read_console_messages` shows no error (acceptance item 2).

## Gate focus for auditors
Only things that could put a wrong number or date in front of the user, or corrupt persisted data:
- The sync timestamp: set only when the GET succeeded and positions were applied, never on failure; a failure line never shown after a later success; "showing HH:MM:SS" names the last success, not the failure; `undefined` from a mocked/legacy caller is not read as failure.
- The stale-curve sentence: last-point date and value are the raw newest snapshot (never a resampled point, never mismatched with `lastSnapshotDate`); the "Open P&L today" figure is exactly the footer's `openTotals(positions).openPnL`; sign and Unicode minus; the symbols named are the unquoted ones.
- Timezone and trading-day logic: ET date derivation, weekend and pre-09:30 stepping, DST days, string comparison of ISO dates; the notice never shown before the first post-sync performance read, with no open positions, or for the Realized curve; backend snapshot dates are server-local while the reference is ET (a point dated the next calendar day in CET still counts as current).
- The dashed segment and shaded gap never imply a value the page does not state in text (open: ends at the stated live figure; equity: no dashed line).
- The alert gate: no toast raised from a failed sync's stale quotes; no change to alert evaluation rules.
- Persistence: `partialize` still only `positions`; no persisted field added, so no version bump; `localStorage` blob unchanged (tested).
- Hydration: no clock- or locale-derived text rendered on the server pass.
